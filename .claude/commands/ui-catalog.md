# Catalog a UI kit: $ARGUMENTS

Build (or rebuild) a concrete inventory of one app's reference UI kit so UI work borrows real components instead of guessing. Output goes to `apps/<app>/ui-catalog.md`, which that app's `ui-kit.md` imports.

## 0. Resolve target
- The first token of `$ARGUMENTS` is the **app** under `apps/`. If missing, ask which app.
- Kit root: a second token if given, else the vendored path in `apps/<app>/ui-kit.md`.
- If the kit root isn't a real directory, stop and ask — do not guess.

## 1. Scan (read-only — never modify kit files)
Inventory the Dart source under the kit root:
- **Reusable widgets** — classes extending `StatelessWidget` / `StatefulWidget`, plus shared helpers. Grep for `class .* extends State(less|ful)Widget` and helper method signatures.
- **Theme tokens** — the theme file(s): exact accessors for colors, typography, spacing.
- **Screens** — group by feature folder; for large folders record `folder + count + representative screens`, not every file.
- **Also available** — Cupertino/platform widgets, form inputs, charts, loaders/shimmer, i18n: note availability and where to look.

## 2. Write apps/<app>/ui-catalog.md
Overwrite the whole file — it is fully generated. A compact lookup index, not a raw dump:
- Header: auto-generated by `/ui-catalog <app>`, the date, a note that manual edits are overwritten.
- `## Theme tokens` — accessors for colors / text / spacing.
- `## Reusable widgets` — one line each: `Name — path — one-line purpose`.
- `## Shared helpers` — `Helper.method(...) — path — purpose`.
- `## Screens by feature` — `feature -> folder (count): representative screens`.
- `## Also available` — cupertino, forms, charts, loaders, i18n — one line each, with where to look.
Summarize oversized groups (folder + count); keep every entry to one line.

## 3. Report
- Print counts (widgets, helpers, screen folders) and the output path.
- Flag anything unclassified for manual confirmation.
- Do NOT edit `ui-kit.md` or touch any kit source file.
